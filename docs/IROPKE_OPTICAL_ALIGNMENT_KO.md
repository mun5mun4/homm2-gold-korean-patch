# 이롭게 바탕체의 작은 크기 높이 보정

이 문서는 `v0.9.0-beta.14`의 글자 높이 보정을 설명합니다. beta.13에서 확인된 작은 크기 글리프의 처짐을 교정하며, 기존 한글 메인 메뉴를 함께 유지합니다.

## 관찰

수정 전 beta.13의 `영웅` 버튼에서 일반 글꼴의 `영` 전경은 y=0..12, `웅`은 y=2..13입니다. 작은 글꼴은 각각 0..10, 2..11입니다. 두 크기에서 글자 중심이 1.5픽셀 어긋납니다. 실제 게임 ICN은 v3 생성 결과와 같으며, crop 좌표 유실이나 메인 메뉴 이미지 문제가 아닙니다.

224px에서 측정한 같은 글자 형태를 게임 크기로 환산하면 차이가 훨씬 작습니다. 작은 크기로 래스터화하면서 아래로 처짐이 커지는 이롭게 바탕체 음절을 교정합니다. 나눔고딕코딩과 맑은 고딕의 같은 표본은 이 현상이 없어 일반 글꼴 전체의 기준선은 바꾸지 않습니다.

## 범위

- 원본 Iropke Batang Medium SHA-256 `5910F97BAED6C6E0B8538E40D326B169E0A510357E20DD9003ABABCE2CE1CC69`, face 0에만 적용합니다.
- 해결된 픽셀 크기 14px와 11px만 대상으로 합니다. 기본 설치와 같은 파일을 직접 선택한 사용자 글꼴 설치의 결과는 같습니다.
- 전경 중심은 양 끝 픽셀을 포함해 `(glyph.top + glyph.bottom - 1) / 2`로 계산합니다. 원래 FreeType bearing에 대한 중심 기준은 각각 -6과 -5입니다.
- 기준보다 0.5픽셀 넘게 아래로 처진 일반 41자·작은 29자를 통째로 1픽셀 올립니다. 다른 크기·글꼴·문자는 그대로 유지합니다.
- `영/웅`의 중심 차이는 1.5에서 0.5픽셀로 줄고, 아래쪽 전경은 같은 y에 놓입니다. `주/조/소`, `가/고/구/그/기`와 원래 중심이 높은 `초/호/효/흐/츠`는 바꾸지 않습니다.

원래 마스크와 `glyph.top`은 보존하고 `_FaceLayout.optical_offsets`에 보정값을 따로 기록합니다. 렌더링과 그림자 경계 통계가 같은 위치 함수를 사용합니다. 글리프 크기·가로 이동량·팔레트·획 모양은 유지하며 전경은 잘리지 않습니다. 위로 이동해 생긴 하단 여백에는 원래 그림자 규칙을 정상 적용합니다.

## 설치 기록과 보존

렌더러 ID는 `pillow-freetype-monochrome-v4-iropke-optical-alignment`, 기준선 정책은 `logical-cell-bearing-with-iropke-optical-offset-v4`입니다. 기존 셀·fit·crop·shadow 계약은 유지합니다. 패처는 정확히 고정된 과거 v3 manifest와 receipt를 계속 해석하며 v2의 하단 기준선과 구별합니다.

일반 버튼·모집 비용 명패도 보정된 글리프를 사용해 재생성합니다. 장식 메인 메뉴 3개 리소스와 네 글꼴의 기존 256개 슬롯, EXE·문자열 은행·캠페인은 그대로입니다. 사용자 파일과 게임 데이터에는 트랜잭션 설치·복구 검증을 적용합니다.

## 검사

`tests/test_iropke_optical_alignment.py`는 측정된 대상 문자, 실제 `영/웅` 경계, 874자 전체 전경 좌표의 정확한 평행 이동, 무보정 글자의 바이트 보존, 같은 글꼴의 기본·사용자 모드 일치와 해시·face·크기 제한을 검사합니다. 기존 버튼 중앙 배치·메인 메뉴 고정·과거 설치 기록 검사도 유지합니다.

GOG·이롭게 글꼴 입력을 사용한 전체 검사 160개 중 159개를 통과했습니다. 변경하지 않은 beta.6 영상 EXE 재생성 검사 1개는 별도 입력을 지정하지 않아 제외했습니다. 새 검토용 EXE로 공개 beta.13 설치본의 두 번째 AGG 교체 실패·51파일과 v3 receipt 복원·복구·재업그레이드·검증·제거를 수행했고, 최종 순정 50파일 복원과 저장 파일·설정 보존까지 확인했습니다.
